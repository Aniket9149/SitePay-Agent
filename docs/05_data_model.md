# Data Model (Phase 1)

Source of truth: `backend/app/models/` and migration `0001`. A structure test (`tests/unit/test_backend_static_structure.py`)
checks that every model table and column also exists in the migration. That test reads source code only.
The tables have **not** been created in a real database in this environment (SQLAlchemy is not installed here).

## Conventions (SP-01 owns these, all workstreams follow them)

- Primary keys are UUID text (36 characters), generated by the application. They cannot be guessed or counted.
- Every table has `created_at` and `updated_at`, timezone aware, stored in UTC. Naive times are refused by the column type.
- Money is `Numeric(18, 2)`, never a floating point type. Rule F2.
- Constraint names follow a naming convention so migrations and rollbacks are predictable.
- Every business table carries `organization_id`, and every query filters by it (tenant separation).
- Foreign keys use `ON DELETE RESTRICT`. Records are never silently removed by a cascade.
- A workstream adds its own tables through its own migration. The migration chain is linear: the next one must set `down_revision = "0001"`.

## Tables

| Table | Purpose | Key constraints |
|---|---|---|
| users | A person who can log in | unique email, scrypt password hash, `is_active` |
| organizations | A company, the unit of tenant separation | `country_pack` |
| memberships | A user in an organisation with one role | unique (user, organization), role limited to the five known roles |
| projects | A construction project | unique (organization, name), contract value not negative, end date not before start date |
| sites | A site or block inside a project | unique (project, name), carries `organization_id` |
| refresh_tokens | Issued refresh tokens, for rotation and revocation | `revoked_at`, `replaced_by_token_id` |
| audit_logs | Permanent record of every action | unique (chain_scope, chain_position), hash chain, append only |

## Relationships

```
users 1---n memberships n---1 organizations 1---n projects 1---n sites
users 1---n refresh_tokens
organizations 1---n audit_logs ;  users 1---n audit_logs (actor)
```

## Audit log

- Each row stores who did what to which record, before and after values, when, and an optional reason.
- Rows are chained per organisation (or the "platform" scope) by SHA-256 hash. Editing or removing a row breaks every later hash.
- Append only is enforced in three places: the ORM refuses updates and deletes, database triggers refuse them again,
  and `find_broken_audit_position` detects tampering after the fact.
- The SQLite trigger SQL was executed in tests. The PostgreSQL trigger SQL was **not** executed anywhere yet.
- Action names follow `namespace.verb` (see `docs/interface_contracts/SP01_SHARED_CONTRACTS.md`).
