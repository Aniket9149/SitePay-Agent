# SP-01 Shared Contracts

Owner: SP-01 Architect. Code: `backend/app/contracts/`. Status of every item is stated plainly below.

**Implemented and tested** means the code exists and its tests were run (see `docs/tracker/TEST_RECORDS.md`).
**Proposed** means it is a convention other workstreams are asked to follow, with no integration yet.
No other workstream's code has been seen or integrated by SP-01. Nothing here claims otherwise.

## 1. Ownership of records

Each kind of record has exactly one owning workstream. Only the owner creates, changes or deletes it.
Other workstreams store a reference and ask the owner for details. No workstream reads another's tables.

| Workstream | Owns these record kinds |
|---|---|
| SP-01 Architect | user, organization, membership, project, site, audit_entry |
| SP-02 Evidence | evidence_item, evidence_link |
| SP-03 Quantum | work_package, activity, measurement |
| SP-04 Contract | contract, contract_clause, variation |
| SP-05 Ledger | calculation, payment_claim, claim_line |
| SP-06 Sentinel | none (quality assurance owns tests and gates, not business records) |

Status: ownership map implemented and tested (`entity_references.py`). Tables for SP-02 to SP-05 do not exist yet.

## 2. References

- Identifiers are UUID text, generated by the owner, never guessable counters.
- A reference is `kind:uuid`, for example `project:3f2a8c1e-...`. It is a logical pointer, not a database foreign key.
- Every business record carries `organization_id`. Every query filters by it (tenant separation).
- Status: `EntityReference` implemented and tested.

## 3. Review and approval states

`draft -> in_review -> approved | rejected`. Rejected returns to draft. Approved may become superseded.

Rules, enforced by `check_transition`:
- Approval cannot skip review.
- Only a **person** can approve or reject. An agent or the system never can (rule A2).
- Default roles allowed to decide: owner, manager, engineer. **Open question** for the owner: who may approve in a small company. Change `DECIDING_ROLES` after the answer, through a change request.
- A rejection needs a reason.

Status: implemented and tested, including an exhaustive check of every disallowed transition.
Not yet connected to any record. SP-05 Ledger and SP-04 Contract are expected to use it for claims and variations.

## 4. Audit actions

Format `namespace.verb`, lowercase, for example `project.created`. Each workstream writes only its own namespaces:

| Namespace | Owner |
|---|---|
| user, organization, membership, project, site, review | SP-01 |
| evidence | SP-02 |
| work_package, activity, measurement | SP-03 |
| contract, variation | SP-04 |
| calculation, claim | SP-05 |

Adding a namespace is a change to `contracts/audit_actions.py`. The audit writer (`record_audit_event`) now
refuses an action that is malformed or in an unregistered namespace.
Status: implemented. Rules tested; the audit writer wiring is verified by source scan only, because the database
code cannot run in the current environment.

## 5. Quantities and money

- A quantity is an exact `Decimal` plus a mandatory unit: sqm, cum, rm, nos, kg, tonne (rule C2).
- Money is an exact `Decimal` plus a three letter currency code. Floats are always refused (rule F2).
- JSON form keeps amounts as text so they never pass through floating point.
- These are value shapes only. Rounding, totals and calculation belong to SP-05 Ledger and SP-03 Quantum.
- Status: implemented and tested. Adoption by other workstreams is pending.

## 6. Paging

Every list route accepts `limit` (1 to 100, default 50) and `offset`. Services fetch `limit + 1` rows and
`build_page` returns `items`, `limit`, `offset`, `has_more`, `next_offset`.
Status: implemented and tested. The Phase 1 list routes still return plain lists. Moving them to this envelope
changes their response shape, so it needs a change note when done.

## 7. API conventions already in place (Phase 1)

- Version prefix `/api/v1`. Health routes `/health` and `/health/ready` are unversioned.
- Errors always look like `{"error": {"code": "...", "message": "...", "details": {...}}}`.
- Money fields are exact decimals. Cross-company access answers "not found", not "forbidden".
- Status: implemented, **not run** in this environment (needs FastAPI). See the tracker.
